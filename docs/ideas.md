## 1. 名前を「Daily Quest」に変える

- **変える場所**: ホーム画面のアプリ名（`project.yml` の `CFBundleDisplayName`）、ウィジェットの名前と説明、アプリ内の表示、README・要件定義書・Obsidian ノート。紹介動画は変更済み。
- **変えない場所**: Bundle ID（`com.arimayuuki.RPGTodo`）、App Group、プロジェクト名・フォルダ名。Bundle ID を変えると、入っているデータやウィジェットの設定が引き継がれないため。利用者には見えない部分なので、そのままでよい。
- **確認すること**
  - App Store に同じ名前のアプリがないか（App Store の名前は他と重複できない）。「Daily Quest」は一般的な言葉なので、取られている可能性がある。その場合は「Daily Quest - 冒険Todo」のように副題をつける。
  - 商標に引っかからないか。
- **一緒に検討**: 「タスク」→「クエスト」への用語の統一（「今日のクエスト」「クエストを追加」など）。「Todo」の言葉をどこまで残すか。

## 2. 使い方ガイド

- **初回起動のガイド**（3〜4枚のスライド）: 「クエストを追加 → 完了すると仲間が増える → 100% で全員集合 → ウィジェットや図鑑も」。最後の1枚で勇者（戦士の男女）を選ぶ（残っている作業「初回起動の勇者選択」とまとめて作る）。
- **あとから見られるヘルプ**: 設定タブに「使い方」。仲間が増える仕組み（20% ごとに1人）、日替わりの抽選、繰り返し、カレンダー連携、ウィジェットの追加方法（ホーム画面を長押し →「＋」）。
- **その場のヒント**: 初めて図鑑を開いたとき、初めてカレンダータブを開いたときに、一度だけ吹き出しで説明する。
- **見せ方**: 勇者や仲間のキャラが説明役になる（例: スライムのプルンが案内する）。図鑑の「ひとこと」と同じ口調にする。
- **決めること**: 何枚にするか（多いと飛ばされる）。「スキップ」を必ず付ける。

## 3. テンプレート機能

- **やりたいこと**: よく使う複数のタスクを1つのまとまりとして保存し、ワンタップでまとめて追加する。
  - 例: 「朝のルーティン」＝洗顔・ストレッチ・朝食、「出勤日」＝メール確認・日報・明日の準備、「週末の家事」＝洗濯・掃除・買い出し。
- **今ある「繰り返し」との違い**
  - 繰り返し: 1件ずつ、毎日・平日などに**自動**で出る。
  - テンプレート: 複数件を、使いたい日に**手動**でまとめて出す。
  - 発展案: テンプレートにも「毎週月曜に自動で追加」などの繰り返しを付けられるようにする。
- **画面のイメージ**
  - ホームの「…」メニュー、または追加ボタンの長押しで「テンプレートから追加」。
  - 「今日のタスクをテンプレートとして保存」で、今日の内容からかんたんに作れる。
  - 設定タブに「テンプレートの管理」（作成・編集・並べ替え・削除）。
- **データ**: `QuestTemplate`（名前・アイコン・中身のリスト〔タイトル・時刻・カテゴリ〕・任意の繰り返し）。追加すると、通常の Todo として1件ずつ作る。
- **決めること**: 同じ日に同じテンプレートを2回追加したときの扱い（警告する／重複を飛ばす）。テンプレートの数や中身の件数の上限。
- **達成率への影響**: テンプレートで一度に多く追加すると、仲間が増えにくくなる。そのままでよいか検討する。

## 4. キャラのアニメーション

- **これまでの決定**: v0.7 で「静止画1枚（歩かない）」に決めた。理由は、絵の制作量と電池（常に動かさない、要件 F-04）。
- **段階を分けて進める**
  1. **軽い動き（絵の追加なし）**: 今の静止画を SwiftUI で動かす。
     - 待機中にゆっくり上下に揺れる（呼吸のような動き）。キャラごとにタイミングをずらす。
     - タスク完了のたびに、パーティが小さく跳ねる。
     - キャラをタップすると、ジャンプしてひとこと（図鑑の `quote`）を吹き出しで話す。
     - 「視差効果を減らす」がオンなら動かさない。アプリが前面のときだけ動かす（電池対策）。
  2. **コマ送り（絵の追加あり）**: 待機2〜4コマ、勝利ポーズなど。キャラ数×コマ数の絵が必要。GPT で同じキャラを何枚も描くと見た目がぶれやすいので、手間が大きい。1 の反応を見てから決める。
- **ウィジェット**: WidgetKit は常に動くアニメーションができない。切り替わるときの小さな動きだけになる。

## 5. RPG 風の見た目に切り替え

- **やりたいこと**: 今の画面は iPhone 標準の見た目（システムのフォント・リスト）。設定で「見た目: シンプル／RPG」を選べるようにし、RPG を選ぶと紹介動画のような画面になる。
- **RPG の見た目で変わるところ（案）**
  - フォント: 見出しや数字をドット絵風のフォントにする。本文は読みやすさのため、標準フォントのままか、読みやすいドット風フォントにする。
  - カード: 白い角丸カードの代わりに、紺色の背景に白い二重の枠の「ウィンドウ」（昔の RPG のメニュー画面風）。
  - チェック: 丸いチェックの代わりに、ドット絵の宝箱・旗・剣などのアイコン。完了すると「クエスト達成！」の小さな表示。
  - ボタン・タブ: ドット絵風のアイコン。選んでいる項目に「▶」のカーソル。
  - 効果音（任意・既定はオフ）: 完了したときの短い音。紹介動画の反省から、耳障りにならない音にする。
- **フォントの権利**: 日本語が使えて、アプリに入れてよい（商用 OK の）ドット風フォントを選ぶ。候補: DotGothic16（SIL Open Font License・Google Fonts）、PixelMplus（M+ ライセンス）など。採用前にライセンスを確認する。
- **気をつけること**
  - 読みやすさ: 文字の大きさの設定（ダイナミックタイプ）やダークモードでも読めること。読み上げ（VoiceOver）を壊さないこと。
  - ウィジェットも RPG 風に合わせるか（ウィジェットにも同じ設定を反映できる）。
  - 作り方: 色・フォント・枠を「テーマ」として1か所にまとめ、画面はテーマを参照する形にする（どちらの見た目も同じコードで動く）。

## 6. キャラの進化（進化アイテム）

- **流れ（2026-10-14 の追記）**
  1. タスクを完了した累計の数に応じて、「進化アイテム」がたまっていく（例: 5件完了で1個）。
  2. アイテムを、進化させたいキャラに「チャージ」する。必要な数はレアリティで変わる（例: なかま 10個・モンスター 15個・魔王 25個・スーパースター 40個）。
  3. 必要な数がたまると「進化できる」状態になる。
  4. そのキャラが**次に仲間として現れたとき**に、進化した姿で登場する（進化の特別な演出つき。「〇〇は進化した！」）。
- **画面**
  - 図鑑のキャラ詳細に「進化ゲージ」（チャージ済み / 必要数）と「チャージする」ボタン。
  - 図鑑の上部や設定に、手持ちの進化アイテムの数。
  - 進化済みのキャラは、図鑑で進化前と進化後の両方を見られる。
- **データ**
  - アイテムの獲得数: 「完了したクエストの累計」から計算する。完了を付けたり外したりして増やせないよう、Todo ごとに「アイテムを渡したか」を1回だけ記録する（または日付が確定した日の完了数だけ数える）。
  - 新しく保存するもの: キャラごとのチャージ量・進化したかどうか・進化した日（`EvolutionRecord`）、使ったアイテムの数。
  - 進化した姿の絵: `art/sprites/{id}_evo.png`（キャラ数ぶんの絵が必要。7 のキャラ追加とまとめて作るとよい）。
- **決めること**
  - アイテム1個あたりの完了数、レアリティごとの必要数（運用しながら調整）。
  - 勇者も進化するか（勇者は毎日いるので、別の基準にする案）。
  - 進化後も、元の姿で出すことを選べるか。
  - 進化の段階は1段階か、2段階以上か（段階が増えるほど絵が増える）。
- **以前の案との関係**: 前に書いた「仲間になった日数で★が上がる」は、絵を作らずにできる軽い版として残す（★ランク・称号・カードの枠の色）。

## 7. キャラを今の倍に（25 → 約50）

- **今**: 勇者2・職業16・モンスター4・魔王2・スーパースター1。
- **増やす案**（約25体）
  - 職業（男女で別キャラ）: 侍・踊り子・吟遊詩人・錬金術師・竜騎士・格闘家・商人・狩人 など 8職×2 ＝ 16体
  - モンスター: ゴブリン・ミミック・ウルフ・キノコ・妖精・ワイバーン など 6体
  - レア枠: 魔王の側近、第2のスーパースター（スーパースターのライバル）など 2〜3体
  - 季節・イベントのキャラ（年末年始・ハロウィンなど）は、別の企画として後で考える。
- **作り方**: 今と同じ流れ。GPT で一覧シートを作る（同じ絵柄・細かさ）→ `tools/sprite-pipeline` の `--hires` で切り出し → `CharacterCatalog` に1件ずつ足す → 紹介文を書く（`docs/character-profiles.md`）。コードの変更はほぼ要らない。
- **気をつけること**
  - キャラが増えると、1体あたりの出やすさが下がる。特にスーパースターがさらに出にくくなる。重み（10 / 5 / 3 / 2）を見直す。
  - 図鑑のコンプリートまでの日数が伸びる。長く遊べる一方で、「いつまでも埋まらない」と感じないか。
  - 既存の有名キャラに似ていないかの確認が、数に比例して増える。
  - アプリの容量（256px の画像 1枚 約 40〜80KB なので、進化後の絵を含めて 100体でも数MB で問題ない）。

## 8. ヘルスケア連携（歩数・体重など）

- **やりたいこと**: iPhone の「ヘルスケア」アプリのデータを読み取り、健康のクエストに使う。
  - 歩数: 「今日 8,000 歩」のクエストを作ると、歩数が届いた時点で自動で完了になる。進み具合（5,230 / 8,000 歩）を行に表示する。
  - 体重: 「体重を記録する」クエストが、ヘルスケアに今日の記録があれば自動で完了。記録の画面で体重の推移を見られる（任意）。
  - ほかの候補: 睡眠時間、運動時間（ワークアウト）、マインドフルネスの時間、水分。
- **作り方**: HealthKit（Apple の健康データの仕組み）。読み取りだけにする（ヘルスケアに書き込まない）。カテゴリ「健康」と相性がよい。
- **気をつけること**
  - 許可: 項目ごとに利用者の許可が必要。何のために読むかの説明文を用意する。拒否されても普通のクエストとして使えるようにする。
  - プライバシー: 健康データは特に慎重に扱う。端末の外に送らない（今の方針どおり）。App Store の審査で、ヘルスケアを使う理由をきちんと説明する必要がある。
  - ウィジェット: iPhone がロック中は健康データを読めないことがある。ウィジェットの歩数表示は、アプリが最後に読んだ値を使う。
  - 自動完了のタイミング: アプリを開いたとき・ウィジェットの更新時・バックグラウンドの更新時に確認する（リアルタイムではない）。

|---|---|---|
