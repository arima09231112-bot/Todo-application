## 1. 名前を「Daily Quest」に変える

- **変える場所**: ホーム画面のアプリ名（`project.yml` の `CFBundleDisplayName`）、ウィジェットの名前と説明、アプリ内の表示、README・要件定義書・Obsidian ノート。紹介動画は変更済み。
- **変えない場所**: Bundle ID（`com.arimayuuki.RPGTodo`）、App Group、プロジェクト名・フォルダ名。Bundle ID を変えると、入っているデータやウィジェットの設定が引き継がれないため。利用者には見えない部分なので、そのままでよい。
- **確認すること**
  - App Store に同じ名前のアプリがないか（App Store の名前は他と重複できない）。「Daily Quest」は一般的な言葉なので、取られている可能性がある。その場合は「Daily Quest - 冒険Todo」のように副題をつける。
  - 商標に引っかからないか。
- **一緒に検討**: 「タスク」→「クエスト」への用語の統一（「今日のクエスト」「クエストを追加」など）。「Todo」の言葉をどこまで残すか。

## 2. テンプレート機能

- **やりたいこと**: よく使う複数のタスクを1つのまとまりとして保存し、ワンタップでまとめて追加する。
  - 例: 「朝のルーティン」＝洗顔・ストレッチ・朝食、「出勤日」＝メール確認・日報・明日の準備、「週末の家事」＝洗濯・掃除・買い出し。
- **今ある「繰り返し」との違い**
  - 繰り返し: 1件ずつ、毎日・平日などに**自動**で出る。
  - テンプレート: 複数件を、使いたい日に**手動**でまとめて出す。
  - 発展案: テンプレートにも「毎週月曜に自動で追加」などの繰り返しを付けられるようにする。
- **画面のイメージ**
  - ホームの「…」メニュー、または追加ボタンの長押しで「テンプレートから追加」。
  - 「今日のタスクをテンプレートとして保存」で、今日の内容からかんたんに作れる。
  - 設定タブに「テンプレートの管理」（作成・編集・並べ替え・削除）。
- **データ**: `QuestTemplate`（名前・アイコン・中身のリスト〔タイトル・時刻・カテゴリ〕・任意の繰り返し）。追加すると、通常の Todo として1件ずつ作る。
- **決めること**: 同じ日に同じテンプレートを2回追加したときの扱い（警告する／重複を飛ばす）。テンプレートの数や中身の件数の上限。
- **達成率への影響**: テンプレートで一度に多く追加すると、仲間が増えにくくなる。そのままでよいか検討する。

## 3. キャラのアニメーション

- **これまでの決定**: v0.7 で「静止画1枚（歩かない）」に決めた。理由は、絵の制作量と電池（常に動かさない、要件 F-04）。
- **段階を分けて進める**
  1. **軽い動き（絵の追加なし）**: 今の静止画を SwiftUI で動かす。
     - 待機中にゆっくり上下に揺れる（呼吸のような動き）。キャラごとにタイミングをずらす。
     - タスク完了のたびに、パーティが小さく跳ねる。
     - キャラをタップすると、ジャンプしてひとこと（図鑑の `quote`）を吹き出しで話す。
     - 「視差効果を減らす」がオンなら動かさない。アプリが前面のときだけ動かす（電池対策）。
  2. **コマ送り（絵の追加あり）**: 待機2〜4コマ、勝利ポーズなど。キャラ数×コマ数の絵が必要。GPT で同じキャラを何枚も描くと見た目がぶれやすいので、手間が大きい。1 の反応を見てから決める。
- **ウィジェット**: WidgetKit は常に動くアニメーションができない。切り替わるときの小さな動きだけになる。

## 4. キャラを今の倍に（25 → 約50）

- **今**: 勇者2・職業16・モンスター4・魔王2・スーパースター1。
- **増やす案**（約25体）
  - 職業（男女で別キャラ）: 侍・踊り子・吟遊詩人・錬金術師・竜騎士・格闘家・商人・狩人 など 8職×2 ＝ 16体
  - モンスター: ゴブリン・ミミック・ウルフ・キノコ・妖精・ワイバーン など 6体
  - レア枠: 魔王の側近、第2のスーパースター（スーパースターのライバル）など 2〜3体
  - 季節・イベントのキャラ（年末年始・ハロウィンなど）は、別の企画として後で考える。
- **作り方**: 今と同じ流れ。GPT で一覧シートを作る（同じ絵柄・細かさ）→ `tools/sprite-pipeline` の `--hires` で切り出し → `CharacterCatalog` に1件ずつ足す → 紹介文を書く（`docs/character-profiles.md`）。コードの変更はほぼ要らない。
- **気をつけること**
  - キャラが増えると、1体あたりの出やすさが下がる。特にスーパースターがさらに出にくくなる。重み（10 / 5 / 3 / 2）を見直す。
  - 図鑑のコンプリートまでの日数が伸びる。長く遊べる一方で、「いつまでも埋まらない」と感じないか。
  - 既存の有名キャラに似ていないかの確認が、数に比例して増える。
  - アプリの容量（256px の画像 1枚 約 40〜80KB なので、50体でも数MB で問題ない）。

## 5. キャラの進化

- **やりたいこと**: 仲間になった回数（日数）が一定に届くと、そのキャラが進化する。
  - 例: 10日で「★2」、30日で「★3（進化）」。図鑑の「仲間になった日数」（`Discovery.days`）がそのまま使える。
- **何が変わるか（案）**
  - 軽い版（絵なし）: 名前の前に称号がつく（「熟練の」「伝説の」）、★のランク、カードの枠の色、キャラのまわりのオーラ（SwiftUI の演出）。
  - 本格版（絵あり）: 進化後の姿の絵に変わる（装備が豪華になる、など）。キャラ数×段階数の絵が必要になるので、4 と同時に考えると量が大きい。
- **画面**
  - 図鑑のカードに★と「あと3回で進化」の表示。
  - 進化の瞬間に、ホームで特別な演出（光る→姿が変わる→「〇〇は進化した！」）。3 のアニメーションとつながる。
  - パーティに出るときは、進化後の姿・称号で出る。
- **データ**: 進化の段階は、日ごとの記録から計算できる（新しく保存しなくてよい）。進化の演出を見たかどうかだけ、1件ずつ保存する。
- **決めること**: 何回で進化するか（出やすいキャラとレアなキャラで回数を変えるか）。勇者も進化するか（勇者は毎日いるので、連続達成日数などで別の基準にする）。進化しても元の姿を選べるか。
