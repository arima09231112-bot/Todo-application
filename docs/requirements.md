# RPG型Todoアプリ 要件定義書

- 版数: v0.1（ドラフト）
- 作成日: 2026-10-13
- 対象: iPhone（iOS ネイティブアプリ＋ホーム画面ウィジェット）
- 元資料: 「RPG型Todoアプリ 要件定義・実装指示書」（ChatGPT との事前相談内容）

本書は元資料を開発着手できる粒度に落とし込んだものです。元資料で曖昧だった点は「仕様決定（案）」として本書で定義し、ユーザー判断が必要な点は「12. 確認事項」にまとめています。

## 1. プロジェクト概要

### 1.1 コンセプト

「日常のタスクを、RPGの冒険に変えるTodoアプリ」

ユーザー自身が勇者となり、その日のTodoを達成するほど仲間が加わってパーティが大きくなる。達成率を数値で見せるだけでなく、**キャラクターが増える・隊列が伸びる**という視覚的な変化で達成感を伝える。

### 1.2 目的・成功指標

| 目的 | 指標（個人利用の目安） |
|---|---|
| 毎日自然に開きたくなる | 1日1回以上の起動 / ウィジェット確認 |
| Todo操作がストレスにならない | 追加: 2タップ＋入力、完了: 1タップ |
| 達成が楽しく感じられる | 節目到達時に必ず加入演出が出る |

### 1.3 基本方針

1. Todo管理部分は iOS 標準アプリ（リマインダー等）並みにシンプルにする。
2. ゲーム要素はドット絵キャラクターと冒険フィールドに集約し、操作UIと視覚的に分離する。
3. ウィジェットを主要機能として扱う。
4. 当日の進捗は日付変更でリセット、過去の履歴は保存する。
5. アカウント登録・クラウドサーバー不要。端末内で完結する MVP をまず完成させる。

## 2. 対象プラットフォームと技術構成

### 2.1 決定事項（案）

依頼が「iPhone向け」であり、ウィジェット・カレンダー連携が重要機能であるため、**iOS ネイティブ（SwiftUI）** を採用する。React Native 等はウィジェットがどのみちネイティブ実装になるため、メリットが小さい。

| 領域 | 採用技術 | 備考 |
|---|---|---|
| 言語 | Swift 6 | |
| UI | SwiftUI | |
| データ保存 | SwiftData | App Group 共有コンテナでウィジェットと共有 |
| ウィジェット | WidgetKit ＋ App Intents | iOS 17 以降のインタラクティブウィジェットで完了操作 |
| カレンダー | EventKit | 読み取りのみ。予定は変更しない |
| 通知 | UserNotifications（ローカル通知） | サーバー不要 |
| ドット絵描画 | SwiftUI `Image` ＋ `.interpolation(.none)`、`TimelineView` でフレーム切替 | SpriteKit は不要と判断（必要になれば後から導入） |
| テスト | Swift Testing / XCTest | |

### 2.2 動作環境

- 最低対応OS: **iOS 17.0**（SwiftData・インタラクティブウィジェット・EventKit の新権限APIが揃う最低ライン）
- 対応端末: iPhone のみ（iPad 対応はスコープ外）
- 画面向き: 縦固定
- 開発環境: **Mac ＋ Xcode（最新安定版）が必須**。実機確認には Apple ID（個人利用なら無料のパーソナルチームでも可、ただし7日ごとの再署名が必要。継続利用には Apple Developer Program 加入を推奨）

> 補足: 現在のリポジトリは空で、この作業環境（Linux）では iOS アプリのビルドはできません。そのため、達成率計算・パーティ判定・日付処理などの**ロジックは UI から独立した Swift Package（`RPGTodoCore`）として実装**し、Linux 上でもユニットテストを回せる構成にします（4章参照）。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| 対象日 | Todo が属する日（＝その日のリストに表示される日）。`date` で保持 |
| 当日の有効なTodo | 対象日が今日で、削除されていないTodo |
| 達成率 | 3.2 の式で算出する当日の割合（0〜100、整数） |
| 勇者 | ユーザー自身を表す主人公キャラクター。常に先頭に1人 |
| 仲間 | 達成率の節目で加入するキャラクター（最大5人） |
| 節目（マイルストーン） | 20 / 40 / 60 / 80 / 100% |
| 日付変更 | 端末のローカルタイムゾーンで 0:00 を跨いだ時点 |

## 4. 機能要件

機能IDの優先度: **P0 = MVP必須 / P1 = MVPに入れたい / P2 = 次期以降**

### 4.1 Todo管理

| ID | 機能 | 優先度 | 詳細 |
|---|---|---|---|
| T-01 | Todo追加 | P0 | タスク名のみ必須。その他は任意。ホーム画面からワンタップで追加シートを開く |
| T-02 | Todo編集 | P0 | 行タップで編集シート |
| T-03 | Todo削除 | P0 | 左スワイプで削除。誤操作対策として数秒間の「元に戻す」を表示（P1） |
| T-04 | 完了／未完了切替 | P0 | 行左のチェック円をタップ。完了時は緑のチェック＋軽い触覚フィードバック |
| T-05 | 対象日・時刻設定 | P0 | 対象日の既定値は今日。時刻は任意 |
| T-06 | カテゴリ設定 | P0 | 仕事 / プライベート / 健康 / その他（既定: その他）。色付きの小ラベルで表示 |
| T-07 | 今日のタスク一覧 | P0 | 並び順: 未完了 → 完了。各グループ内は時刻あり（昇順）→ 時刻なし（作成順） |
| T-08 | 未完了タスクの確認 | P1 | 過去日の未完了Todoを一覧表示。「今日に移す」操作を提供（4.1.1） |
| T-09 | 過去日の履歴確認 | P0 | 冒険の記録画面から日付を選び、その日のTodoと達成率を参照（閲覧のみ） |
| T-10 | 通知 | P1 | 時刻を設定したTodoに対し、指定時刻にローカル通知 |
| T-11 | 繰り返しTodo | P2 | 毎日／平日／曜日指定。日課系タスクに有用だが MVP 外 |

#### 4.1.1 仕様決定（案）: 過去日の Todo の扱い

- 未完了Todoは**自動で翌日に繰り越さない**（繰り越すと過去の達成率が変わり、履歴の意味がなくなるため）。
- 日付変更後、過去日のTodoは**読み取り専用**とし、完了状態は変更できない。
- 「今日に移す」を実行すると、今日の日付で**新しいTodoとして複製**し、元のTodoには「繰越済」の印を付ける（元の日の達成率は変わらない）。

### 4.2 達成率の計算

```
達成率 = floor(完了済みTodo数 ÷ 当日の有効なTodo総数 × 100)
```

| ID | 要件 |
|---|---|
| P-01 | 計算は `RPGTodoCore` の単一関数で行い、アプリ・ウィジェット・履歴のすべてがこれを使う |
| P-02 | 端数は**切り捨て**（例: 3件中2件 = 66%）。100% は全件完了時のみ |
| P-03 | Todo 0件の場合は数値を出さず「今日の冒険は準備中」状態とする（パーティは勇者のみ） |
| P-04 | Todo の追加・削除・完了切替・対象日変更のたびに再計算する |

### 4.3 RPGパーティシステム

#### 4.3.1 加入ルール

```
仲間の人数 = floor(達成率 ÷ 20)    （0〜5人）
```

| 達成率 | パーティ |
|---|---|
| 0〜19% | 勇者のみ |
| 20〜39% | 勇者＋仲間1人 |
| 40〜59% | 勇者＋仲間2人 |
| 60〜79% | 勇者＋仲間3人 |
| 80〜99% | 勇者＋仲間4人 |
| 100% | 勇者＋仲間5人（全員集合） |

- Todo件数が少ない日は節目を一度に複数超えることがある（例: 2件中1件で 50% → 2人加入）。その場合は加入演出を順番に再生する。
- チェックを外して達成率が下がった場合は、即座に人数も減らす（減少時は演出なしでフェードアウト）。

#### 4.3.2 仕様決定（案）: 加入演出の再生条件

- 各節目の加入演出は **1日1回のみ**。その日に一度到達した節目は `unlockedMilestones` に記録し、チェックの付け外しを繰り返しても再生しない（演出の乱発防止）。
- 人数表示自体は常に現在の達成率に連動する（記録済みでも、達成率が下がれば人数は減る）。
- 100% 到達時は通常の加入演出の後に「全員集合」の特別演出を再生する。

#### 4.3.3 キャラクター

| 加入順 | 職業 | MVP |
|---|---|---|
| ― | 勇者（ユーザー） | ○ |
| 1 | 剣士 | ○ |
| 2 | 魔法使い | ○ |
| 3 | 僧侶 | ○ |
| 4 | 盗賊 | ○ |
| 5 | 騎士 | ○ |
| ― | 弓使い | 次期（キャラ入れ替え・ランダム加入機能と合わせて追加） |

- 100% 時に「全員集合」となるよう、MVP でも勇者＋仲間5人の**計6キャラ**が必要。
- キャラクターはデータ（職業ID・表示名・スプライト名）で定義し、コードを変えずに追加できる構造にする。

#### 4.3.4 歩行フィールド

| ID | 要件 |
|---|---|
| F-01 | ホーム画面下部に、勇者を先頭に横一列で歩くフィールドを表示 |
| F-02 | 背景はレトロRPG風の草原（地面タイル＋空＋雲程度の簡素なもの）を横スクロール |
| F-03 | 歩行アニメーションは横向きスプライトの複数フレーム（4フレーム）切替、約 6〜8fps |
| F-04 | アニメーションは画面表示中のみ動作。バックグラウンド・非表示時は停止 |
| F-05 | 「視差効果を減らす」設定がオンの場合は歩行・スクロールを停止し静止表示 |
| F-06 | 仲間が増えると隊列の最後尾に加わる（右から歩いて合流する演出） |

### 4.4 カレンダー連携

| ID | 要件 | 優先度 |
|---|---|---|
| C-01 | 初回利用時に EventKit でカレンダーのフルアクセス許可を求める（読み取りに必要） | P0 |
| C-02 | 今日（P1: 明日まで）の予定を取得し、開始・終了時刻とタイトルを表示 | P0 |
| C-03 | 予定ごとにTodo候補を生成し、ユーザーが採用／除外を選べる | P0 |
| C-04 | 候補は編集してから採用できる | P1 |
| C-05 | 元のカレンダー予定は一切変更しない（読み取り専用） | P0 |
| C-06 | 同じ予定から候補・Todoを重複生成しない（4.4.2） | P0 |
| C-07 | 予定の変更・削除を検知し、紐づくTodoに「予定が変更されました」を表示（Todo自体は自動削除しない） | P1 |
| C-08 | 設定画面から連携を解除できる（解除後は取得しない。OS側の権限取り消しへの案内も表示） | P0 |
| C-09 | 外部サービス（Google Calendar API 等）との直接連携 | P2（iOS のカレンダーに Google アカウントを追加すれば EventKit 経由で取得可能なため、当面不要） |

#### 4.4.1 候補生成方式

- MVP は**端末内のテンプレート（キーワード辞書）方式**とする。外部AIへの送信は行わない（予定はプライバシー性が高いため）。

| キーワード例 | 候補 |
|---|---|
| 会議・定例・MTG | 「{予定名}の資料を確認する」 |
| 訪問・商談・打ち合わせ | 「{予定名}の提案資料を準備する」 |
| レビュー | 「{予定名}の修正箇所を確認する」 |
| 該当なし | 「{予定名}の準備をする」 |

- 候補の時刻は既定で予定開始の30分前とする（ユーザーが変更可）。
- 次期検討: 端末内で動く Apple の生成AI機能（対応端末・OS限定）を使った候補提案。採用する場合もテンプレート方式をフォールバックとして残す。

#### 4.4.2 重複防止

- 繰り返し予定は同一の識別子を共有するため、**「予定の識別子＋その回の開始日時」** を重複判定キーとし、Todo の `calendarEventKey` に保存する。
- 既に採用済み・除外済みの予定は候補一覧に再表示しない（除外済みは「除外した予定を表示」で復帰可能）。

### 4.5 ウィジェット

| ID | 要件 | 優先度 |

### 4.6 冒険の記録（履歴）

| ID | 要件 | 優先度 |
|---|---|---|
| H-01 | 日別の達成率・完了数／総数・加入した仲間の人数を一覧／カレンダー形式で表示 | P0 |
| H-02 | 過去日を選んでその日のTodoとパーティを閲覧 | P0 |
| H-03 | 連続達成日数（ストリーク） | P1 |
| H-04 | 週次・月次の平均達成率 | P1 |
| H-05 | 簡易グラフ（直近7日／30日の達成率推移） | P2 |

**仕様決定（案）: 連続達成日数の定義** — 「達成率100%の日」が連続した日数。Todo 0件の日は連続を途切れさせず、カウントもしない（休日扱い）。今日がまだ100%でない場合は昨日までの連続日数を表示する。

### 4.8 日付変更処理

| ID | 要件 |
|---|---|
| D-01 | 日付判定は端末のローカルタイムゾーン・0:00 区切り |
| D-02 | アプリが前面に戻ったとき、および起動中に 0:00 を跨いだとき（`significantTimeChange` 通知）に日付変更を判定 |

## 5. データモデル

元資料のモデルを、実装方針に合わせて次のように整理する。**DailyProgress は Todo から再計算可能な派生データ**であり、履歴表示の高速化と日付確定のスナップショットとして保持する。

### 5.1 Todo

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | UUID | ○ | |
| title | String | ○ | 1〜100文字 |
| date | Date（日付のみ） | ○ | 対象日 |
| time | Date? | | 時刻（元資料の dueTime） |
| category | Enum | ○ | work / private / health / other |
| isCompleted | Bool | ○ | |
| completedAt | Date? | | |
| notificationEnabled | Bool | ○ | 既定 false |
| calendarEventKey | String? | | 予定識別子＋開始日時（4.4.2） |
| carriedOverTo | UUID? | | 「今日に移す」で作られた複製先 |
| sortOrder | Int | ○ | |
| createdAt / updatedAt | Date | ○ | |

> 元資料の `dueDate`（期限）は `date`（対象日）と役割が重なるため、MVP では `date` に統合する。「○日までに終わらせる」型の期限管理は P2 で検討。

### 5.2 DailyProgress（日次スナップショット）

| 項目 | 型 | 説明 |
|---|---|---|
| date | Date（一意キー） | |
| totalTasks | Int | |
| completedTasks | Int | |
| completionRate | Int? | Todo 0件なら nil |
| partyMemberCount | Int | 仲間の人数（勇者を含まない、0〜5） |
| unlockedMilestones | [Int] | その日に到達した節目（演出再生済み管理を兼ねる） |
| isFinalized | Bool | 日付変更で確定済みか |

> 元資料の `PartyState` は、日付と節目情報が DailyProgress と重複するため統合した。「現在のパーティ」は今日の DailyProgress から導出する。

### 5.3 CalendarSuggestionRecord

| 項目 | 型 | 説明 |
|---|---|---|
| calendarEventKey | String（一意キー） | |
| eventTitle | String | 変更検知用 |
| startAt / endAt | Date | 変更検知用 |
| status | Enum | adopted / dismissed |
| lastSyncedAt | Date | |

> 予定そのものは EventKit から都度取得し、アプリ側には重複防止と変更検知に必要な情報のみ保存する。

### 5.4 Settings

`UserDefaults`（App Group 共有）に保存: `theme`, `notificationsEnabled`, `calendarAccessEnabled`, `selectedCalendarIds`。

### 5.5 Character（静的定義・コード内またはJSON）

`id`, `jobName`, `joinOrder`, `spriteSetName`（例: `swordsman_walk_right_0..3`）

## 6. 画面要件

> 元資料にある画面イメージ画像は今回のやり取りには添付されていなかったため、以下はテキストでの構成案です。画像をいただければ本章と突き合わせて修正します。

### 6.1 画面一覧・遷移

```
[ホーム：今日の冒険] ─┬─ (+) ──────────→ [Todo追加シート]
  (タブ1)              ├─ Todo行タップ ─→ [Todo編集シート]
                       └─ 予定カード ───→ [カレンダー連携：候補一覧]
[冒険の記録] (タブ2) ── 日付タップ ───→ [日別詳細]
[設定] (タブ3)
```

タブバーは 3 タブ（今日の冒険 / 冒険の記録 / 設定）。

### 6.2 ホーム画面：今日の冒険

```
┌──────────────────────────┐
│ 10月13日（火）                 │
│ 今日の冒険                     │  ← 大見出し（iOS Large Title）
│ ┌──────────────────────┐ │
│ │  60%   3 / 5 クリア       │ │  ← 進捗カード（円形ゲージ＋数値）
│ └──────────────────────┘ │
│ 今日の予定 (2)          ＞     │  ← カレンダー予定（折りたたみ可）
│ ┌──────────────────────┐ │
│ │ ○ 会議資料を確認   10:00 │ │
│ │ ○ ジョギング 30分   健康 │ │  ← Todoリスト（カード）
│ │ ● 牛乳を買う        済  │ │     完了は緑チェック＋薄字
│ └──────────────────────┘ │
│                         (+)   │  ← 追加ボタン（青・右下）
├──────────────────────────┤
│ ☁       ☁                    │
│ 🧝 🗡 🧙 ⛪ ← 歩く           │  ← ドット絵フィールド（高さ約140pt）
│▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
└──────────────────────────┘
```

- 上部（Todo管理）は白背景＋角丸カード、下部（フィールド）はドット絵背景で明確に分離する。
- Todo 0件時: リスト部に「今日の冒険は準備中」と追加ボタンへの誘導、フィールドは勇者が待機している静止状態。
- 加入演出はフィールド上で再生し、Todo 操作を妨げない（モーダルを出さない）。100% 時のみフィールド上に「全員集合！」のバナー（2〜3秒で自動的に消える）。

### 6.3 Todo追加・編集シート

- ハーフシート表示。開いた時点でタスク名にフォーカスし、キーボードを表示。
- 項目: タスク名（必須）/ 対象日（既定: 今日）/ 時刻（オフが既定）/ カテゴリ（セグメント選択）/ 通知（時刻設定時のみ表示）
- キーボードの「完了」でそのまま保存（最短: ＋ → 入力 → 完了）。
- 編集時のみシート下部に「削除」ボタン。

### 6.4 カレンダー連携：候補一覧

- 今日の予定を時刻順にリスト表示し、各予定の下にTodo候補を表示。
- 各候補に「追加」「除外」ボタン。「すべて追加」ボタンも用意。
- 未許可時は説明文と「カレンダーへのアクセスを許可」ボタン。拒否済みの場合は設定アプリへの案内。

### 6.5 冒険の記録

- 上部: 連続達成日数・今週の平均達成率のサマリーカード
- 中部: 月カレンダー（各日に達成率の色ドット: 100%=緑、1〜99%=青の濃淡、0件=グレー）
- 日付タップ: その日のTodo一覧・達成率・その日のパーティ（静止画）

### 6.6 ウィジェット

| サイズ | 表示内容 |
|---|---|
| 小 | 達成率（大きな数字）、完了数／総数、勇者＋仲間の小さなドット絵（最大6体を縮小表示） |
| 中 | 左: 達成率とパーティ / 右: 未完了Todoを最大3件（チェック付き） |
| 大 | 上: 達成率・完了数 / 中: Todoを最大6件 / 下: フィールド背景つきパーティ |

- 表示しきれない件数は「ほか n 件」と表示。
- Todo 0件時は「今日の冒険は準備中」＋勇者のみ。

## 7. デザイン要件

### 7.1 UI

| 項目 | 指定 |
|---|---|
| 基調色 | 白（ダークモード時は iOS 標準のシステム背景色） |
| メインカラー | 青（iOS システムブルー相当） |
| 完了アクセント | 緑（iOS システムグリーン相当） |
| カテゴリ色 | 仕事=青、プライベート=紫、健康=緑、その他=グレー（小ラベルのみで使用） |
| カード | 角丸 12〜16pt、控えめなシャドウ |
| フォント | システムフォント（SF Pro / ヒラギノ）。ダイナミックタイプ対応 |
| アイコン | SF Symbols |

### 7.2 キャラクター・ドット絵

| 項目 | 指定 |
|---|---|
| スプライトサイズ | 1体 **24×24px**（16×16 では職業の描き分けが難しいため）。表示時は整数倍に拡大 |
| 頭身 | 2〜2.5頭身のデフォルメ |
| 向き | MVP: 右向き（歩行）と正面（待機・演出）の2方向。後ろ向きは次期 |
| 歩行フレーム | 4フレーム（右足前・直立・左足前・直立） |
| 色数 | 1体あたり輪郭色を含め 8〜12色程度。輪郭は濃色ではっきり描く |
| 描き分け | 武器・帽子・マントの形と色で職業を判別できるようにする（剣士=剣と青、魔法使い=とんがり帽子と紫、僧侶=白い法衣と杖、盗賊=頭巾と緑、騎士=鎧と盾） |
| 拡大描画 | ニアレストネイバー（補間なし）で拡大し、にじませない |
| 権利 | 既存ゲーム（ポケモン・ドラクエ等）のキャラクター・スプライト・素材は一切使用しない。完全オリジナルとする |

- 開発初期は**仮素材**（コードやドット絵ツールで作った簡易スプライト）で動作を優先し、後から本素材に差し替える。ファイル名規約（`{職業ID}_{向き}_{フレーム番号}`）を守れば差し替えのみで反映される構造にする。
- 本素材の制作手段（自作 / 依頼 / 有償素材の購入）は確認事項（12章）。

## 8. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | Todo 完了タップから達成率・パーティ表示更新まで体感遅延なし（100ms 以内目標）。アプリのコールドスタートは 2秒以内 |
| バッテリー | アニメーションは画面表示中のみ。常時のバックグラウンド処理は行わない |
| オフライン | 全機能がネットワークなしで動作する |
| プライバシー | データはすべて端末内（＋任意で iCloud バックアップ）。カレンダー情報を外部に送信しない。トラッキングなし |
| データ保全 | アプリ更新時にデータを失わない（SwiftData のスキーマ移行を考慮）。エクスポートでバックアップ可能（P1） |
| アクセシビリティ | VoiceOver で Todo 操作と達成率が読み上げられる（パーティは「勇者と仲間3人」のように説明文を付与）。視差効果を減らす設定に対応 |
| ローカライズ | 日本語のみ（文字列は後から英語化できるよう String Catalog で管理） |
| 品質 | ドメインロジック（達成率・加入人数・節目判定・日付変更・重複キー生成）はユニットテストで網羅 |

## 9. スコープ

### 9.1 MVP に含める

- Todo の追加・編集・削除・完了切替、対象日・時刻・カテゴリ
- 達成率計算と 0件時の準備中表示
- パーティ人数の変化、加入演出（1日1回／節目）、100% 特別演出
- オリジナルドット絵 6 キャラ（仮素材可）と歩行フィールド
- 日付変更でのリセットと履歴保存、履歴閲覧
- ウィジェット 小・中・大（閲覧＋タップでアプリ起動）
- カレンダー予定の取得とテンプレート方式の候補生成・採用／除外・重複防止

### 9.2 MVP に含めない（次期以降）

- 繰り返しTodo、期限（締切日）管理、サブタスク
- 弓使い等の追加キャラ、キャラの入れ替え・装備・レベル
- AI による候補提案
- Google Calendar API 等の外部連携、複数端末同期（iCloud 同期）
- ロック画面ウィジェット、Apple Watch、iPad
- Android 対応

## 10. 開発フェーズと完了条件

元資料のフェーズを踏襲しつつ、各フェーズの完了条件（受け入れ基準）を明確化する。

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| Phase 0 | 開発環境・プロジェクト雛形 | Xcode プロジェクト・ウィジェット拡張・App Group・`RPGTodoCore` パッケージが作成され、空アプリが実機で起動する |
| Phase 1 | Todo 基本機能 | T-01〜T-07, T-09 が動作。達成率が操作に応じて正しく更新される。`RPGTodoCore` のテストが通る |
| Phase 2 | RPG システム | 仮スプライトで 6 キャラが表示され、達成率に応じて人数が変化。歩行アニメーション・加入演出・100% 演出が動作 |
| Phase 3 | ウィジェット | 3 サイズが表示され、アプリでの変更が反映される。0:00 に新しい日の表示へ切り替わる（P1: ウィジェットから完了操作） |
| Phase 4 | カレンダー連携 | 許可取得 → 予定表示 → 候補の採用／除外。同じ予定から重複しない。連携解除できる |
| Phase 5 | 履歴・改善 | 記録画面（日別）、ストリーク・週次月次集計、本素材への差し替え、UI 調整 |

### 10.1 MVP 受け入れテスト（元資料 10章の具体化）

| # | 条件 | 確認方法 |
|---|---|---|
| 1 | Todo を追加・編集・削除できる | 追加 → 名称変更 → 削除が一覧に反映される |
| 2 | 完了で達成率が更新される | 5件中3件完了で「60% 3/5」と表示される |
| 3 | 達成率に応じてパーティ人数が変化 | 上記で仲間3人。1件チェックを外すと 40% で仲間2人 |
| 4 | オリジナルドット絵で表示 | 6キャラが補間なしのドット絵で表示される |
| 5 | 仲間加入の演出 | 20% 到達で演出が1回出る。外して付け直しても再生されない |
| 6 | 日付変更で新しい日のパーティ | 端末の日付を翌日にするとパーティが勇者のみになる |
| 7 | 過去の記録を保持 | 記録画面で前日の達成率・人数が確認できる |
| 8 | ウィジェットで確認できる | ホーム画面のウィジェットに達成率とTodoが表示され、アプリでの完了が反映される |
| 9 | カレンダーから候補作成 | テスト予定「定例会議」から候補が出て、採用するとTodoになる。再度開いても重複しない |
| 10 | 操作が直感的 | Todo の追加が「＋→入力→完了」、完了が1タップで行える |

## 11. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| iOS ビルドに Mac が必要 | 開発自体ができない | Mac ＋ Xcode の用意を前提とする。ロジックは Linux でもテストできるよう分離 |
| ウィジェットの更新が OS 依存 | アプリとの表示ずれ | 変更時の更新要求＋0:00 のタイムラインエントリ。仕様として遅延を許容 |
| ドット絵素材の制作負荷 | Phase 2 の遅延 | 仮素材で先行し、命名規約で後から差し替え |
| 予定タイトルだけでは作業内容が判断できない | 的外れな候補 | 候補は必ずユーザー確認後に採用。編集して採用可能に |
| 達成率を上げるための付け外し | 演出の価値低下 | 演出は節目ごとに1日1回 |
| 無料のパーソナルチームでの実機署名は7日で失効 | 日常利用が途切れる | 継続利用時は Apple Developer Program（年額）加入を推奨 |
